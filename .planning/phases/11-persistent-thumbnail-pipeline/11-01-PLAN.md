## 1. Executive Summary & Architectural Overview

Phase 11 establishes the high-performance hardware transport serialization, multi-vendor preview extraction, and persistent local thumbnail caching infrastructure for TransferIn.

In fast-paced tethered studio environments (15–30 fps bursts across Fujifilm, Canon, Sony, and Nikon cameras), two major failure modes undermine image throughput and gallery responsiveness:
1. **Half-Duplex USB Endpoint Contention & Packet Interleaving:** Background Tier 2 RAW streaming (30MB–60MB per file) saturates the USB bulk endpoint, blocking low-latency embedded preview fetches (<128KB in <50ms) and risking fatal PTP transaction ID desynchronization.
2. **Asynchronous Disk Flush Race Conditions & 0-Byte Corrupt Placeholders:** Prematurely updating Room database entities or Coil image loaders before file output buffers flush to flash storage causes Coil to load 0-byte corrupt files, permanently caching blank black boxes and corrupting portrait orientation (loss of EXIF Tag `0x0112`).

Phase 11 definitively eliminates these hazards through a decoupled, priority-arbitrated intake architecture.

### Core Capabilities Delivered:
1. **Sub-50ms Multi-Vendor Embedded Preview Extraction (`THUMB-01`):** High-speed binary header parsers for Fujifilm (`.RAF`), Canon (`.CR3`), Sony (`.ARW`), and Nikon (`.NEF`) extracting embedded JPEG preview byte streams in $<50\text{ms}$ without transferring full multi-megabyte RAW files over USB.
2. **Two-Stage Atomic Thumbnail Persistence & Lifecycle Store (`THUMB-02`):** `ThumbnailStorageManager` managing private app storage (`context.cacheDir/thumbnails/{fingerprint}.jpg`) using two-stage transactional commits (`.tmp` write $\to$ `fos.fd.sync()` $\to$ POSIX `renameTo`), 0-byte validation, 500MB bounded LRU disk management, and a 3-day TTL / logout pruning policy that survives post-upload RAW file eviction (`PURGED_LOCAL`).
3. **Two-Tier Priority USB Mutex Arbitration (`THUMB-03`):** Priority-aware locking on `SafeUsbTransportManager` prioritizing Tier 1 interactive preview extraction (<50ms) over cooperative chunked Tier 2 RAW cloud uploads on the half-duplex USB endpoint.
4. **Deterministic Coil Compose ImageLoader Architecture (`THUMB-04`):** Custom `ImageLoader` configured with 25% JVM heap memory cache, 250MB LRU disk cache, deterministic compound cache keys (`"thumb_${deviceId}_${objectHandle}_${fingerprint}"`), and EXIF Tag `0x0112` orientation normalization.
5. **Automated Unit & Regression Test Suite:** Comprehensive test harness validating atomic disk writes, zero-byte prevention, priority lock arbitration, and multi-vendor EXIF preservation across 100 consecutive simulated shots.

## 4. Work Breakdown Structure & Task List

### Task 1: `ThumbnailStorageManager.kt` with Atomic Two-Stage Writes, Verification & Lifecycle Eviction (`THUMB-02`)

- **Target Files:**
  - `app/src/main/java/com/rvmeur/transferin/data/thumbnail/ThumbnailStorageManager.kt`
  - `app/src/main/java/com/rvmeur/transferin/data/thumbnail/ThumbnailStorageConfig.kt`
- **Implementation Details:**
  1. Define `ThumbnailStorageManager` managing the dedicated directory `context.cacheDir/thumbnails/` (or configurable root directory).
  2. Implement atomic two-stage disk commit in `saveThumbnail(fingerprint: String, jpegBytes: ByteArray): File?`:
     - Validate input payload: reject empty fingerprints, empty byte arrays, or corrupted non-JPEG byte streams (must start with `0xFF, 0xD8`).
     - Check if destination file `File(thumbnailsDir, "${fingerprint}.jpg")` already exists and has `length() > 0`. If so, update `lastModified` timestamp and return the existing file.
     - Create unique staging file: `File(thumbnailsDir, "thumb_${fingerprint}_${System.nanoTime()}.tmp")`.
     - Write bytes via `FileOutputStream(tempFile)`.
     - Call `fos.flush()` followed by `fos.fd.sync()` to force physical kernel and flash hardware buffer synchronization.
     - Close stream.
     - Perform atomic rename: `tempFile.renameTo(finalFile)`. If `renameTo` returns false, fallback to `java.nio.file.Files.move` with `ATOMIC_MOVE` / `REPLACE_EXISTING`.
     - Post-write verification: Assert `finalFile.exists() && finalFile.length() > 0`. If check fails, delete corrupted file and return `null`.
     - Enforce LRU cache budget asynchronously or synchronously: if `getUsedBytes() > maxCacheBytes` (default 500MB), trigger `pruneToSize()`.
  3. Implement lifecycle and pruning methods:
     - `getThumbnailFile(fingerprint: String): File?`: Retrieves thumbnail, updates `lastModified`, validates `length() > 0`, and purges 0-byte corrupt entries.
     - `hasThumbnail(fingerprint: String): Boolean`: Instant existence check.
     - `deleteThumbnail(fingerprint: String): Boolean`: Removes specific thumbnail file.
     - `pruneStaleThumbnails(maxAgeMs: Long = 3 * 24 * 60 * 60 * 1000L): Int`: Iterates directory and deletes files older than 3 days.
     - `purgeAllThumbnails(): Boolean`: Aggressive cleanup invoked on user logout or session termination.
     - `pruneToSize(targetSizeBytes: Long = maxCacheBytes): Long`: Evicts oldest files by `lastModified` ascending until total directory size $\le \text{targetSizeBytes}$.
     - `getUsedBytes(): Long`: Calculates total byte footprint of active thumbnails and temporary staging files.
  4. Ensure safety invariant: Persistent thumbnails remain intact and accessible in `cacheDir/thumbnails/` even after RAW transit files in `/cache/transit/` are evicted post Google Drive upload (`PURGED_LOCAL`).
- **Test-Driven Verification:**
  - `ThumbnailStorageManagerTest`:
    - Verify atomic write produces valid non-zero file and cleans up `.tmp` staging file.
    - Verify `fd.sync()` ensures data persistence.
    - Verify corrupted 0-byte writes fail verification and do not pollute the gallery index.
    - Verify 3-day TTL deletes files older than 72 hours while preserving fresh files.
    - Verify 500MB bounded LRU prune evicts oldest accessed files first.
    - Verify `purgeAllThumbnails()` cleanly empties directory on session teardown.

### Task 3: Two-Tier Priority Mutex in `SafeUsbTransportManager.kt` (`THUMB-03`)

- **Target Files:**
  - `app/src/main/java/com/rvmeur/transferin/data/usb/core/SafeUsbTransportManager.kt`
  - `app/src/main/java/com/rvmeur/transferin/data/usb/core/UsbPriorityMutex.kt`
- **Implementation Details:**
  1. Define `UsbTransferPriority` enum:
     - `TIER_1_PREVIEW` (High priority: embedded preview extraction, shutter event polling, control transfers)
     - `TIER_2_STREAMING` (Standard background priority: chunked RAW/transit OkHttp uploads)
  2. Implement coroutine-safe `UsbPriorityMutex`:
     - Maintain two FIFO wait queues: `tier1Queue` and `tier2Queue`.
     - When a lock is requested with `TIER_1_PREVIEW`, it is placed at the head of the priority arbitration queue.
     - When the current lock holder releases the lock, any waiting `TIER_1_PREVIEW` coroutine is immediately resumed before any waiting `TIER_2_STREAMING` coroutine.
     - Within the same priority level, strict FIFO ordering is maintained.
     - Support non-cancellable release in `finally` blocks to prevent lock leaks on coroutine cancellation.
     - If transport is terminated (`beginDrainAndClose`), wake all waiting coroutines with `UsbTransportClosedException`.
  3. Integrate `UsbPriorityMutex` into `SafeUsbTransportManager`:
     - Provide priority-aware locking extensions:
       ```kotlin
       suspend fun <T> withPriorityLock(
           priority: UsbTransferPriority = UsbTransferPriority.TIER_2_STREAMING,
           action: suspend () -> T
       ): T
       suspend fun <T> withTier1PreviewLock(action: suspend () -> T): T
       suspend fun <T> withTier2StreamingLock(action: suspend () -> T): T
       ```
     - Preserve backward compatibility with `ioMutex: Mutex` where necessary.
  4. Ensure cooperative chunking in `DirectStreamingEngine`:
     - Large RAW transfers acquire and release the Tier 2 lock per 64KB/128KB chunk, providing natural yield points for incoming Tier 1 preview extraction requests.
- **Test-Driven Verification:**
  - `SafeUsbPriorityMutexTest`:
    - Verify that when multiple Tier 2 transfers are waiting, a newly arriving Tier 1 request acquires the lock first as soon as the active holder releases.
    - Verify FIFO fairness within Tier 1 and Tier 2 queues.
    - Verify zero lock leakage or deadlock when a coroutine is cancelled while holding or waiting for the lock.
    - Verify `beginDrainAndClose` immediately aborts all waiting priority lockers with `UsbTransportClosedException`.

  1. Implement `ThumbnailImageLoaderProvider` providing a singleton Coil `ImageLoader`:
     - **Memory Cache:** 25% of available JVM heap (`MemoryCache.Builder(context).maxSizePercent(0.25).strongReferencesEnabled(true).build()`).

  2. Implement `ThumbnailCacheKey`:
     - Generates deterministic compound cache keys:
       ```kotlin
       fun build(fingerprint: String, deviceId: String? = null, objectHandle: Int? = null): String {
           return "thumb_${deviceId ?: "local"}_${objectHandle ?: 0}_${fingerprint}"
       }
       ```
     - Provide `ImageRequest.Builder.thumbnailCompoundKey(fingerprint, deviceId, objectHandle)` setting both `memoryCacheKey` and `diskCacheKey`.

     - Update `UploadedGalleryScreen.kt` and `CameraGalleryScreen.kt` to use the deterministic cache keys and load from `ThumbnailStorageManager` file paths or persistent thumbnail URIs.
     - Eliminate gallery tile flickering, stale thumbnail reuse, and 90° portrait rotation bugs.
