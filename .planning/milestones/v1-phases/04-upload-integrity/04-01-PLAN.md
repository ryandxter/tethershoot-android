    Create the complete two-phase upload infrastructure that wires end-to-end from the upload worker to the SFTP server.

    1. **Enhance SftpClient interface** (SftpClient.kt):
       - Add `uploadWithTwoPhaseCommit()` method with signature: `suspend fun uploadWithTwoPhaseCommit(host: String, port: Int, username: String, password: String, localUri: Uri, remoteDirectory: String, remoteFileName: String, expectedSize: Long, startOffset: Long, onProgress: ((bytesTransferred: Long, totalBytes: Long) -> Unit)?): Result<Unit>`
       - Add `deletePartFile()` method with signature: `suspend fun deletePartFile(host: String, port: Int, username: String, password: String, remoteDirectory: String, remoteFileName: String): Result<Unit>`

    2. **Implement in JschSftpClient** (JschSftpClient.kt):
       - Implement `uploadWithTwoPhaseCommit()`:
         - Upload to `$remoteDirectory/$remoteFileName.part` using OVERWRITE mode with SftpProgressMonitor
         - After upload completes, call `channel.stat(partPath).size` to verify remote size matches expectedSize
         - If size mismatch, delete the .part file and return `Result.failure(SizeMismatchException(...))`
         - If size matches, call `channel.rename(partPath, finalPath)` for atomic commit
       - Implement `deletePartFile()` using existing `withSftp()` pattern
       - Add extension property `ChannelSftp.stat(path: String): SftpATTRS` to avoid naming conflict with `channel.stat()`

    3. **Create UploadCheckpointManager** (UploadCheckpointManager.kt):
       - Constructor takes `TransferQueueDao` as dependency
       - Add companion object constants: `CHECKPOINT_INTERVAL_BYTES = 1_048_576L` (1MB), `CHECKPOINT_INTERVAL_MS = 30_000L` (30s)
       - Add instance properties: `lastCheckpointTime: Long = 0L`, `lastCheckpointBytes: Long = 0L`, `checkpointMutex: Mutex`
       - Add `suspend fun getResumeOffset(queueItemId: String): Long` - queries TransferQueueDao.getById(), returns bytesUploaded if status is "UPLOADING", else 0L
       - Add `suspend fun hasCheckpoint(queueItemId: String): Boolean` - returns getResumeOffset() > 0
       - Add `suspend fun maybeSaveCheckpoint(queueItemId: String, bytesUploaded: Long, totalBytes: Long)` - uses mutex lock, checks if bytesSinceLast >= 1MB OR timeSinceLast >= 30s, then calls saveCheckpoint()
       - Add `suspend fun saveCheckpoint(queueItemId: String, bytesUploaded: Long, totalBytes: Long)` - calculates progressPercent, calls TransferQueueDao.updateProgress() with status "UPLOADING"
       - Add `suspend fun clearCheckpoint(queueItemId: String)` - resets lastCheckpointTime and lastCheckpointBytes to 0L

    4. **Create TwoPhaseUploadHandler** (TwoPhaseUploadHandler.kt):
       - Constructor takes `SftpClient` and `UploadCheckpointManager` as dependencies
       - Add exception class: `class SizeMismatchException(val remoteSize: Long, val expectedSize: Long) : Exception("Size mismatch: remote=$remoteSize, expected=$expectedSize")`
       - Add `suspend fun upload(queueItem: TransferQueueItemEntity, localUri: Uri, host: String, port: Int, username: String, password: String): Result<Unit>`:
         - Get resume offset: `val startOffset = checkpointManager.getResumeOffset(queueItem.id)`
         - If startOffset > 0, delete any existing .part file for clean resume
         - Call sftpClient.uploadWithTwoPhaseCommit() with startOffset
         - On progress callback: `checkpointManager.maybeSaveCheckpoint(queueItem.id, bytes, total)`
         - On success: `checkpointManager.clearCheckpoint(queueItem.id)`
         - On SizeMismatchException: delete .part file and rethrow
       - Add `suspend fun cleanupPartFile(...)` wrapper that calls sftpClient.deletePartFile()

    DO NOT wire into TransferUploadWorker yet - that is a separate task below.
